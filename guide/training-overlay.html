The one thing to remember

  • Same base model. Both pipelines share Stage 0 (pretraining). The recipes only fork after that, at fine-tuning.
  • The deepest divergence is the reward. Traditional LLMs learn a reward model from human preferences and optimize it with PPO (which needs a critic/value network). Reasoning models use rule-based verifiable rewards (accuracy + format) optimized with GRPO — no reward model, no critic; the group-average reward is the baseline.
  • Reasoning adds a self-improvement loop. The model generates its own data, keeps only correct samples (rejection-sampling SFT), then runs a 2nd RL pass — which is where long chain-of-thought and self-verification (the "aha moment") emerge.

Test yourself — before you reread

You just scanned a dense diagram, which feels like understanding but usually isn't (the "fluency illusion"). Try to recall each answer first, then open it. Struggling for a few seconds is what makes it stick — not rereading.

Which stage is identical for both pipelines, and what does it produce?

Stage 0 — pretraining (internet-scale, self-supervised next-token prediction). It yields a base model that produces real-sounding text but does not follow instructions. Everything after this is where the two recipes diverge.

At which stage do the two paths first fork, and what data does each use there?

They fork at SFT. Traditional: human-annotated instruction / QA pairs (humans write the answers). Reasoning: cold-start on long chain-of-thought traces (<think>…</think> reasoning).

Why can GRPO drop the value/critic network that PPO requires?

PPO needs a learned value network to estimate the baseline it subtracts from rewards. GRPO instead samples a group of outputs per prompt and uses the group-average reward as the baseline — so there's no separate critic to train.

What makes DeepSeek-R1's RL rewards "verifiable," and why does it matter?

They're rule-based — accuracy (is the answer correct?), format, and language-consistency — not a learned preference model. That means no reward model to train, and the signal is far harder to reward-hack. Contrast: Llama 2 trains learned Helpful + Safety reward models from human preference data.

What is the self-improvement loop unique to the reasoning recipe?

Rejection-sampling SFT: the model generates its own data, keeps only the correct samples, and retrains on them — followed by a 2nd RL pass covering all scenarios (helpful + harmless). Optionally, the reasoning is then distilled into smaller dense students (Qwen, Llama). The traditional recipe just ships after RLHF.

Recap · the one thing

Same base, then a fork at SFT — and the deepest change is the reward. Traditional: learned preference reward models + PPO (with a critic). Reasoning: rule-based verifiable rewards + GRPO (no reward model, no critic — group average is the baseline), plus a self-generated rejection-SFT → 2nd-RL loop from which long CoT and self-verification emerge.

Sources: Traditional pipeline — Touvron et al., Llama 2: Open Foundation and Fine-Tuned Chat Models (2023). Reasoning pipeline — DeepSeek-AI, DeepSeek-R1: Incentivizing Reasoning Capability in LLMs via Reinforcement Learning (arXiv:2501.12948).
